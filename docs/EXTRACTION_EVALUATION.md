# Structured extraction evaluation

PDF Tools does not currently provide general structured document extraction.
Its local runtime can read a PDF text layer, inspect AcroForm values, and render
pages or regions for visual inspection. It does not bundle an OCR engine, a
table reconstruction engine, or a system that fills an arbitrary user-provided
JSON schema.

This document defines a small executable calibration for that current boundary.
It is a starting point for measuring future candidates, not a state-of-the-art
claim and not a release gate by itself.

## Claim boundary

Phase 0 uses eight tiny, deterministic, synthetic PDFs. The runner invokes the
source MCP server directly over stdio on one local machine. It does not invoke a
model, a desktop host, an external service, or an external dataset.

The generated report must contain `benchmark_claim_ready: false` and
`calibration_claim_ready: false`. Both values are fixed as `false` by the report
schema. A passing harness therefore cannot
be presented as evidence that PDF Tools, an OCR engine, a model, or a candidate
architecture leads a public benchmark.

The calibration measures current product output exactly as returned. It never:

- calls page rendering OCR;
- converts page text into an invented schema or table result;
- supplies a missing answer on the product's behalf;
- treats missing output, invalid output, or a timeout as a pass;
- removes a failed attempt from the planned denominator.

Harness failures remain distinct from product failures. Setup and controller
faults before a valid MCP handoff are harness failures. Unknown server or tool
faults after handoff are product failures. Every planned case must produce one
retained case record in the same order as the frozen plan.

## Current product surface

| Surface | Current behavior | Phase 0 interpretation |
| --- | --- | --- |
| `read_pdf_content` | Reads the PDF text layer. If the selected text is entirely empty, it may return page 1 as an image. | Text extraction and raster availability are separate. The image is not OCR text. |
| `read_pdf_pages` | Returns bounded page-numbered text. | Supports page provenance, but not region provenance or layout blocks. |
| `search_pdf_text` | Returns literal page-numbered snippets. | Useful retrieval evidence, not structured field extraction. |
| `render_pdf_page` and `render_pdf_region` | Return PNG content with page or region metadata. | Visual input is available, but no local recognized text or table structure is produced. |
| `get_page_analysis` | Reports geometry and PDF.js text, image, and graphics measurements with explicit status. | Useful for local-first routing and failure detection. |
| `read_pdf_fields` and `extract_to_csv` | Read and export AcroForm field values. | Structured form data only. Flattened content, XFA, and page tables are outside this claim. |

The current text path flattens PDF.js items without preserving a general block,
line, column, or cell model. The current image fallback runs only when the
selected text result is entirely empty. A mixed document can therefore contain
born-digital text on one page and an unrecognized raster page elsewhere while
the broad text call reports completion. The mixed-modality fixture makes this
observable without asserting a fix.

## Phase 0 corpus

The manifest and schemas live under `test/fixtures/eval/extraction/`. Every PDF
is generated by `scripts/eval-generate-extraction-fixtures.mjs` and records an
exact SHA-256 digest, provenance, license, privacy class, partition, page
geometry, target schema, typed truth, fact anchors, pages, and top-left point
boxes.

The eight cases are:

| Category | Purpose |
| --- | --- |
| Flat schema | Small born-digital invoice with strings, a date, and a nested money value. |
| Nested schema | Nested address, array, boolean, and wider field coverage. |
| Layout order | Two columns with an explicit logical order. |
| Table | Merged title cell, header row, data rows, and an intentional blank cell. |
| Clean raster | Raster-only receipt with no PDF text layer. |
| Degraded raster | Lower-resolution, lower-contrast rendering of the same receipt truth. |
| Mixed modality | Born-digital first page and raster-only second page. |
| No answer and contradiction | Conflicting recommendations plus absent final values. |

All pages currently use default-origin MediaBox and CropBox geometry. The
manifest records those boxes exactly. Rotated, offset, cropped, `UserUnit`, and
hostile coordinate cases remain outside Phase 0 and must not be inferred from
these results.

## Metrics

The runner reports each family separately. It does not compute one blended
quality score.

- JSON parse records whether a structured candidate exists and parses.
- Schema validity checks a parsed candidate against that case's target schema.
- Field correctness reports true positives, missing leaves, spurious leaves,
  precision, recall, and F1.
- Text coverage and reading order score born-digital fragments by page.
- Table topology and table cells are separate. Cell scoring reports missing and
  spurious cells plus precision, recall, and F1, so extra cells cannot receive a
  perfect score.
- OCR records output coverage plus CER and WER when recognized text exists.
  When PDF Tools returns no recognized text, availability is `unavailable`, the
  coverage score is zero, and CER and WER remain null.
- Raster rendering measures whether the visual page path produced a PNG. It is
  not included in OCR accuracy.
- Evidence page, bounding box, fact, and answer support are separate. Evidence
  must bind the expected source digest and retained tool-result digest. Bounding
  boxes must also fit the recorded page geometry. Fact support requires an
  explicit matching fact identifier, so a matching page snippet alone does not
  receive fact-level credit. Bounding-box support also uses manifest-pinned IoU,
  truth-containment, and page-area thresholds. Answer support remains
  unavailable until a per-answer mapping can require valid JSON, target-schema
  validity, correct relevant fields, and their evidence.
- Latency and Linux server RSS are recorded per case.
- Privacy, fixture license, and bundle cost have separate records. Phase 0 does
  not instrument network syscalls and does not build a package, so those values
  remain bounded or null instead of receiving invented scores.

The direct runner deliberately provides no structured candidate, table
candidate, OCR text, answer, or fact bounding boxes. Current unsupported
capabilities therefore appear as explicit zero and `unavailable` results. Since
each Phase 0 job requires a structured candidate, every current case remains a
product failure even when all lower-level read and render calls complete.

## Current report

The committed run retains all eight planned cases. All eight are product
failures because the current product returns no general structured candidate.
This is the expected and honest Phase 0 result, not a harness failure.

On these synthetic calibration documents, born-digital text coverage and
reading order score 1.0 across six applicable cases, and raster rendering scores
1.0 across three applicable cases. JSON parse, schema validity, field
correctness, OCR, table topology, table cells, fact evidence, bounding-box
evidence, and answer evidence remain unavailable with a score of zero. Page
evidence scores 0.6875 because retained page text supports some, but not all,
expected anchors. These values do not generalize beyond the exact fixtures and
runtime recorded in the report.

## Research frame

Phase 0 uses only synthetic repository fixtures, but its metric separation is
informed by current primary sources:

- [ExtractBench](https://arxiv.org/abs/2602.12247) and its
  [MIT-licensed implementation](https://github.com/ContextualAI/extract-bench)
  report substantial gaps between valid JSON and complete field correctness,
  including a 369-field SEC schema with no valid outputs in the reported run.
  This supports scoring parse, schema, and fields separately.
- [VAREX](https://arxiv.org/abs/2603.15118), the
  [benchmark code](https://github.com/udibarzi/varex-bench), and the
  [IBM Research dataset card](https://huggingface.co/datasets/ibm-research/VAREX)
  study variable-schema extraction and report gains from spatial text as well
  as schema-echo and compliance failures. Candidate use still requires a
  license, privacy, and maintenance review for the exact assets selected.
- [DocScope](https://arxiv.org/abs/2605.08888) and its
  [project repository](https://github.com/MiliLab/DocScope) emphasize complete
  evidence chains rather than answer correctness alone. Its dataset uses a
  noncommercial share-alike license and the repository does not publish a clear
  code license, so it is methodology input only for this project.
- The [KDD table extraction benchmark](https://soricm.github.io/table-extraction-benchmark/)
  and its linked MIT-licensed implementation separate detection, topology,
  content, and calibration measures. Phase 0 follows that separation at a much
  smaller calibration scale.

Reported percentages from another benchmark are context, not a PDF Tools
baseline. PDF Tools results must come from the committed runner and exact report
bytes.

## Proposed local-first routing

Routing should remain observable and fail closed:

1. Inspect page geometry, text status, image status, and form structure locally.
2. Route AcroForm value jobs to the existing form path.
3. Route simple born-digital reads to bounded page text, while retaining page
   identity and extraction status.
4. Treat textless image pages and mixed-modality gaps as requiring raster or OCR
   handling. Rendering alone must not satisfy an OCR result.
5. Route layout and table jobs only to an engine that returns blocks or cells
   with page coordinates and stable evidence identifiers.
6. Validate any general structured candidate against the requested schema, then
   score fields independently and preserve null or unknown states.
7. Require important facts to bind source hash, tool-result hash, page, and a
   valid region when the claim is spatial.
8. Fall back or fail with explicit coverage gaps. Never silently replace a
   missing page, field, cell, or answer.

Candidate engines should run as external adapters first. Bundling requires a
separate review of quality, licenses, redistribution, privacy, offline behavior,
memory, latency, artifact size, native targets, and ongoing maintenance. The
protected PDF.js version must not change as part of this evaluation.

## Reproduce

Generate the fixtures and compare their committed bytes:

```bash
node scripts/eval-generate-extraction-fixtures.mjs --output-dir /tmp/pdf-tools-extraction-fixtures
```

Run the direct current-product baseline:

```bash
node scripts/eval-run-extraction-baseline.mjs
```

Run the focused contract, scorer, hostile-mutation, denominator, and
reproducibility tests:

```bash
npx vitest run test/eval/extraction-phase0.test.js
```

The committed current-product report is
`docs/evidence/extraction-phase0-current-product.v1.json`. It is useful only
within its recorded runtime commit, tool-contract digest, fixture hashes,
platform, architecture, and limitations.
