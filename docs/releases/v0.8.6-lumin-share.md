## Slack Message

Hey team, quick PDF Tools update. We just hardened `v0.8.6`, and I wanted to share the work before we promote it more broadly.

The big theme: PDF Tools now has a real Sign mode in the MCPB viewer. Before this release, the viewer was mostly view/fill/manage/extract. Now Claude can help identify signature/date zones, the UI exposes a Sign tab, users can draw or reuse a saved signature, and signature/date boxes can be placed onto the PDF.

We also hardened the tricky parts of that experience. Claude is now much better at finding, explaining, and placing signatures/dates on real-world PDFs. The prior internal candidates could detect likely signing areas, but the experience was too easy to get subtly wrong on messy forms: a W-9 signature box could drift toward the printed label, rotated pages could show upright signature overlays on sideways pages, and Claude could have useful coordinates in hidden metadata without those coordinates being visible in the actual response it reasoned from.

What changed since the last public release:

- New MCPB viewer Sign mode: Signature and Date zones, Draw signature, saved signatures, manual fields, signing packets, and text stamping.
- Signature/date detection now returns exact visible coordinates in the tool response, so Claude can say where it found a zone and reason from the same data the UI uses.
- W-9 signature/date placement was tuned so the boxes sit on the signing row instead of floating near the labels.
- Rotated-page signing overlays now rotate with the page.
- The signing surface includes inspect-region, region preview, and preview-to-zone flows for PDFs where the automatic detector does not know the right spot.
- Claude now has better PDF reading and visual inspection tools: page-bounded reads, text search, full-page rendering, and region rendering for signatures, stamps, scans, and hard-to-read areas.
- PDF URLs can now be fetched through the local MCP tool instead of relying on sandboxed shell/web fetches.
- Claude Desktop users now get explicit allowed-directory controls for local PDF access.
- Same-document fill/sign flows were hardened so edits preserve the active working file lifecycle instead of multiplying confusing copies.
- CSV bulk-fill handling preserves quoted values with commas.
- XFA form display got a regression pass after `force_xfa=true` fills, including a Claude Desktop sanity check.
- We added a real non-standard municipal PDF test case: the Sandy Springs business-license packet, which has 8 pages and 0 fillable fields but several visible signature/date lines.
- The final `.mcpb` was rebuilt, reinstalled in Claude Desktop, adversarially reviewed, and checked for packaging junk before release.

## Shorter Version

PDF Tools `v0.8.6` is the release where the MCPB gets a real Sign mode: Signature and Date zones, drawn/saved signatures, text stamping, manual placement, and Claude-visible coordinates. Since the last public release it also adds page/region rendering, page-bounded reads, PDF URL fetching, allowed-directory controls, cleaner same-document save behavior, rotated-page signing fixes, XFA display checks, and Sandy Springs' non-standard business-license packet as a real-world fixture. Final MCPB was reinstalled and verified in Claude Desktop; 179 tests are passing. Evidence sheet attached.
