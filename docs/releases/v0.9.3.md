# PDF Tools v0.9.3: Fail-Closed Comparison Geometry

PDF Tools `v0.9.3` hardens visual PDF comparison so an exclusion region may
hide pixels only when both page renders carry the same valid, exact geometry.
If that proof is missing or inconsistent, the tool keeps the pixels visible to
the comparison instead of guessing.

## What improved

Before applying a visual exclusion, PDF Tools now validates the expected native
renderer, whole-page request, coordinate space, PDF view box, rotation,
`UserUnit`, raster dimensions, fixed comparison scale, and the producer's exact
unrounded viewport. Matching bad metadata on both sides is not accepted merely
because it matches.

The guard covers fractional page sizes at raster-ceiling boundaries, rotated
pages, positive non-default `UserUnit` values, malformed or missing geometry,
and two same-sized pixel canvases that describe different logical pages.
Self-consistent supported pages retain the intended one-pixel tolerance;
unsupported mappings receive no masking.

## Scope

This patch changes comparison safety only. It does not change the Shannon
Markdown output shipped in v0.9.2: the reviewed 55-page conversion still
contains exactly 49 recovered alpha symbols, 498 replacement characters, 68
explicit gaps, and Markdown SHA-256
`2e7e4fb71d0ea116a352eb1aa1ed1b06c089969643073394d82e23eb5f6ffee3`.

## Honest limits

PDF Tools reports deterministic differences from the supported local parser
and renderer; it is not a semantic proof that two documents have identical
meaning. It still does not perform OCR, decode every Type-3 font, reconstruct
arbitrary formulas, or infer ambiguous merged tables.
